# pooling-workload-profiler

**KRAKEN 워크로드 분석기 — 커널 분류·페어링 판정·위상 추적**

AI 반도체 컴퓨팅 자원분해 및 자원풀링 기술 개발 (No.RS-2025-02220502)

무엇을 함께 배치해야 서로 덜 방해하는지 판정한다.
워크로드의 커널 구성을 분석해 성격을 분류하고, 두 워크로드를 같은 가속기에 올렸을 때의
적합도를 산출해 배분 정책의 입력으로 공급한다.

---

## 구성

| 경로 | 역할 |
|---|---|
| `kernel_class/`, `kernel_class_v2/` | 커널 분류 엔진 — 연산 집약도와 SM 점유 차원 |
| `fingerprint.py` | 워크로드 지문 — 커널 구성 요약 |
| `pattern_matcher.py` | 패턴 정합 |
| `killer_extractor.py` | 게이팅 대상이 되는 무거운 커널 추출 |
| `online_profiler.py` | 온라인 프로파일링 |
| `phase_online/`, `timeseries/` | 실행 위상 추적, 주기성 분석 |
| `static_estimate/` | 모델 정보 기반 정적 추정 (실행 없이 자원 요구량 산출) |
| `policy_schema.py` | 정책 스키마 |
| `collector/` | 지표 수집 |
| `monitor/` | 실행 지표 로거 |

## 현재 구현 상태

### 동작 확인된 것

**커널 분류**
- 연산 집약도 기준 분류 — 메모리 지향 / 혼합 / 연산 지향
- v2에서 **SM 점유(공간) 차원 추가** — 연산 집약도만으로는 갈리지 않던 페어링 판정을 해소

**페어링 판정**
- 성격이 다른 워크로드를 짝지을수록 적합도가 높다는 원칙을 규칙으로 구현
- 2차원 판정으로 개정 — 두 축의 AND 조건에서 곱(점유 채움) 규칙으로 변경
- 오판 사례를 역추적해 가드 추가

**정적 추정**
- 모델을 실행하지 않고 자원 요구량을 추정 — 배치 이전 판단에 사용

**위상 추적**
- 학습 워크로드의 반복 구간을 온라인으로 식별, 주기성 분석

### 알려진 제약

| 항목 | 내용 |
|---|---|
| 프로파일 범위 | 검증에 쓰인 워크로드 종류가 제한적 |
| 지표 출처 | 장치 수준 지표만 확보 가능 — 프로세스별 귀속은 별도 회계 필요 |

## 앞으로 할 것

- [ ] **워크로드 다양성 확대** — 현재 분류·페어링 검증은 소수 모델에 한정
- [ ] **NPU 워크로드 분류** — 현재 분류 엔진은 GPU 커널 기준. NPU는 실행 단위가 달라 재정의 필요
- [ ] **간섭 정량화 지표** — 현재 간섭은 증상(꼬리 지연)으로 간접 판단. 직접 측정량 정의
- [ ] **프로파일 자동 갱신** — 워크로드 변화 시 재프로파일링 트리거
